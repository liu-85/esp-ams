## YAO_AMS：提交即编译 + 单文件一键烧录固件

用户需求：每次提交自动触发编译；编译后发布**一个**可直接烧录到 ESP32-C3 的
BIN 文件，烧完设备即跑，不需要再单独上传 .py/.mpy。

### 核心原理（踩坑记录）

- ESP32-C3 的官方固件是**从 0x0 起的完整镜像**，所以"单文件"= 官方固件
  (0x0) + 自制 littlefs 文件系统镜像拼接到分区表里 `vfs` 的 offset (0x200000)。
- **致命陷阱**：`_boot.py` 启动时 `vfs.mount(bdev, "/")`，`mp_vfs_autodetect`
  靠 block 0 和 block 1 的 **offset 8 处 `"littlefs"` 魔数**识别文件系统。
  挂载失败会走 `inisetup.check_bootsec()`，首扇区非 0xFF 就打印
  "The filesystem appears to be corrupted" 并**死循环**，永远跑不到用户代码。
- 官方 C3 v1.23.0 分区表：nvs@0x9000(24K)、phy_init@0xf000(4K)、
  factory@0x10000(1984K)、vfs@0x200000(2M, subtype **0x81** 但实际是 **littlefs2**，
  不是 FAT)。
- **版本必须对齐**：v1.23.0 内置 littlefs `LFS2_VERSION=0x00020008`(2.8)。
  pip 的 `littlefs-python` 0.19 自带 littlefs **2.11**。最终决定用**设备同源
  2.8.0 上游源码**自己编译工具生成镜像。
- 本地无 gcc → 用 TinyCC 0.9.27 win64 编译 `tools/lfs_mkfs.c` 做本地验证；
  CI 用 ubuntu 自带 gcc。
