## 主任务：用户报「新推送代码编译烧录后反复重启」→ 实证排查

### 结论：固件本身没问题，重启循环未复现
- 板子当前跑的就是 CI run#29 出的 `esp32s3-ams-firmware.bin`（MicroPython 单文件固件，
  TinyUSB CDC：`VID_303A&PID_4001`，序列号 `123456`；昨天的旧固件是 USB-Serial/JTAG
  `PID_1001`、序列号=MAC）。**区分两种描述符 = 区分两份固件**。
- 实测板子：上电自检通过 → 扫描 6~7 个 WiFi → AP AMS_WIFI 起来 → Web 80 端口 3 worker，
  全程无 traceback；连续运行 15+ 分钟；`boot_stat.json count=2`（boot.py 每次都写，
  循环重启一定会疯涨）→ **没有发生过重启循环**。
- REPL 特点：TinyUSB CDC 不开口，要发 Enter/Ctrl-C 才有 `>>>`；DTR 必须拉高。
- 判决实验：碎堆上关 AP → 重开 AP **不复位**（C3 时代的"esp_wifi_start 碎堆复位"
  在这块 S3 上不成立，free=103840）。
- 最可能的真相：**供电/欠压**（本项目 reset_info.py 的文档就写着"接上负载之后一直
  重启、电机电流声"这个历史症状；PC USB 供电下一切正常）。待用户复现后看
  boot_stat/网页上的复位原因确认（BROWN_OUT / 连续 PWRON = 电源）。

### 顺手抓到并修掉的 BUG（已提交 c301ab6 + 676f8b7）
1. **配网页 WiFi 列表永远为空（我 9-17 引入的回归）**：main.py 预热扫描写的是
   独立 `network_model()` 实例的 `_scan_cache`，AMS_WEB 实例读自己的空缓存。
   修法：`_scan_cache/_scan_ts` 提升为**类属性**（读走 self 回落类属性，
   写必须显式 `network_model._scan_cache =`，否则实例遮蔽）。tests 128/128。
2. **C 版急停失效**：STOP 只排队（最长 8s 才生效）且 handler 漏了 `motor_stop()`。
   加 `s_stop_requested`，循环每 500ms 步检查；无微动分支改等效步进
   （motor_run 同向幂等）；中止的换料不发 resume。
3. **bambu_mqtt.c 接收缓冲 1 字节越界**：恰好 8192 字节报文时 `s_rx_buf[s_rx_len]=0`
   出界；改为 `>= MQTT_RX_BUF_SIZE` 拦截（预留终止符）。
4. C 版 WiFi 管理器一组配网可靠性改进（9-17 夜里写、未提交，本次一起收口）：
   纯 AP 模式 / stop_sta_reconnect / 国家码 CN+满功率 / WPA 混合认证 / 等 AP_START。
