  `network.WLAN(STA_IF)`。空堆一次成功；之后再调只花 16 字节（对象复用）。
  串口实测：空堆 ~200KB → 成功；WiFi 总代价 AP 24,576B + STA 16B。

## 傍晚：「网页打不开」根因 = C3 内存不够（不是网络问题）+ 双开发板改造

用户强烈反馈：加了 OTA 功能之后网页彻底打不开（之前"只是慢但能用"），

### 1) 「网页打不开」的真正根因（两层，第二层才是致命的）

| 层 | 现象 | 结论 |
|---|---|---|
| 表层 | ESP32 默认 WiFi modem-sleep（`pm=1`），持续传输时周期性休眠 → STA 掉线，串口刷 `ECONNABORTED` | `sta.config(pm=0)` 关掉省电后，空应用下 65KB 页面 5.7 秒发完 |
| **根因** | **C3 只有 400KB SRAM**。不加载应用时空闲堆 149KB；**加载应用后只剩约 60KB**，最大连续块更小。WiFi 驱动收发时要动态申请**连续**缓冲 → 申请不到就 `OSError(113)`，重传 9.4 秒后放弃、射频卡死只能复位 | `probe_sf5`（app 已加载、阻塞式 accept、无 asyncio）仍 `ERR OSError(113) free=60256`；`probe_mem_app` 显示光 `ota_update` 就吃 15968B |

→ 加 OTA 之后应用变大，把「偶发」推成「必然」。**pm=0 是必要的，但在 C3 上
不充分**；真正的解法是换 S3。pm=0 与「发送后 drain 再关连接」两处修复已保留
（对 S3 也有益）。

## 深夜：ESP-AMS-S3 —— 用 ESP-IDF 把整个项目重写成 C

用户要求：新建 `esp-ams-s3/`，**按给定目录结构用 ESP-IDF 重写**；每路电磁配

### 结论：3.8MB 静态 SRAM 那类约束从架构上消失了（这是重写的最大收益）

Python 版 main.py 的阶段划分（先开射频 → 预建 `:80` socket → 最后才 import
应用）**全部**是为了绕开"GC 不压缩、最大连续块只剩 3584 字节"。ESP-IDF 下
WiFi 驱动用静态缓冲，`esp_http_server` / `esp-mqtt` 各自跑在独立任务里，
所以：**handler 可以放心写阻塞代码**（扫 WiFi 2 秒、OTA 几十秒都行），
启动顺序可以按逻辑依赖排而不用按内存排。另外有了真正的 **ota_0/ota_1 双分区
OTA**（Python 版单 factory 分区做不到整机固件升级）。

### 本轮修掉的三类真问题（都是"没有编译器就必须靠人眼"的类型）

1. **`esp_get_revision()` 这个 API 根本不存在** → 真名是 `esp_chip_info()`
   填 `esp_chip_info_t`。且 IDF v5.0 起 `esp_chip_info.h` 不再由 `esp_system.h`
   间接包含，必须显式 include。`chip.revision` 格式也变过（v5 是 `100*大+小`）。
2. **`bambu_proto.c` 里中文字符串嵌了裸 ASCII 双引号**
   （`"可能检测到"意面"缺陷…"`）→ 硬语法错误。★ 关键是**这行引号总数是偶数**
   （6 个），所以"数引号奇偶"的判据完全看不见 —— 见下面 lint 的改进。
3. **`OTA_WITH_SEQUENTIAL_WRITES` 是 v3.x 旧名**（v4.0 起改名 `OTA_SIZE_UNKNOWN`，
   值都是 `(size_t)-1`），新版头文件已删掉它 → 改成 `OTA_SIZE_UNKNOWN`。

另外自查出一个**硬件安全缺陷**（不是编译问题）：`motor_apply()` 原来是
"先写 IN1 再写 IN2"，从退料切进料的瞬间**两路同时为高 → H 桥直通 → 烧驱动芯片**，
而函数注释却声称已保证"两路不同时为大"。已改成**先双路清零、再给目标通道赋值**，
并拦截"两路都非 0"的调用。这条和离合的四重仲裁同级，属于硬件红线。

同时从 `sdkconfig.defaults` 删掉两个**不存在的 Kconfig 符号**（只会换来
"unknown config item" 警告并让人误以为已生效）：
- `CONFIG_ESP_WIFI_POWER_SAVE_NONE` —— 根本没这个符号。WiFi 省电在 ESP-IDF 里
  是**运行时**设置，唯一正确位置是 `esp_wifi_set_ps(WIFI_PS_NONE)`
  （已在 `wifi_mgr_init()` 里）。
- `CONFIG_SPIRAM_TYPE_AUTO` —— v4.x 的符号，v5.0 起该 choice 已删除。

### `tools/lint_c.py` 判据被真实 bug 逼着升级（★ 可复用）

原判据是"每行引号数量为奇数 → 可疑"，**被第 2 条 bug 打脸**（那行是偶数）。
改成 **"代码位置出现中文字符"**：C 的标识符只能是 ASCII，中文合法出现的位置
只有字符串和注释，所以剔掉字符串+注释后还能扫到中文 → 一定是字符串被提前截断、
后面的中文掉出来变成了"代码"。**这条零误报**，比奇偶可靠得多。

新增 `--selftest`（8 条内置用例：3 条"必须抓到" + 5 条"不该误报"，含
跨行括号配平、JSON 转义 `\"`、中文只在注释里）。改判据前先跑它。
结果为让 selftest 能喂内存样例，`check_file()` 拆成 `读取 → check_lines(lines)`。
两个命令都返回非 0，可直接当 CI 门禁。

### 项目约定（新增）

- **必须 ESP-IDF v5.x，不能降到 v4.x**：v4 的 `esp_mqtt_client_config_t` 还是
  扁平字段（`uri`/`username`/`password`），会直接编译失败。
- `main/CMakeLists.txt` 的 `REQUIRES` 里 **必须留 `esp_psram`**（哪怕一行它的
  API 都没调）：`CONFIG_SPIRAM*` 这些选项定义在 `esp_psram` 组件自己的 Kconfig
  里，组件不在依赖列表里 Kconfig 就可能不被解析 → 配置被当"未知项"丢掉、
  PSRAM 悄悄没打开（不报错，只是内存少了）。原来占位的 `spiffs` 已移除（未使用）。
- 网页三个文件用 `EMBED_FILES` **编进固件 `.rodata`**，不挂文件系统 ——
  没有"SPIFFS 挂载失败 → 网页打不开"这类故障，也没有额外工具依赖。
- `main.c` 最后一步 `if (web_ok) esp_ota_mark_app_valid_cancel_rollback();`
  **不能省**：开了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` 却不确认，下次重启
  会自动回滚，"升级成功但一重启变回旧版"，极难查。放在最后 = 只有体检通过才确认。

## 当晚：推分支触发 CI，推送前又拦下 1 个"必挂"的坑

用户要求「推一个分支触发 CI 把编译跑通」。推之前先做了推送前核查，结果
**又拦下一个必然导致构建失败的 bug**，以及一批"会静默失效"的配置问题。

### ★ `partitions.csv` 带 UTF-8 BOM —— 必然构建失败（已修）

- 现象：文件开头是 `EF BB BF`。`gen_esp32part.py` 以 **二进制**读入后
  `data.decode()`（默认 utf-8，**不是** utf-8-sig），再用
  `line.strip().startswith('#')` 跳注释 —— **它不做任何 BOM 剥离**。
- 后果：首字符变成 U+FEFF 而不是 `#`，跳过逻辑失效，**这行注释会被当成一条
  分区定义**去解析，然后报 `Field 'type' can't be left empty.`，构建直接失败。
  报错信息完全指不到 "BOM" 上。
- 修法：按字节剥掉 BOM。⚠️ **注意写文件工具会保留/回写 BOM** —— 我用 Write
  重写过一次，BOM 又回来了，最后是用 Python 以 `rb`/`wb` 手动剥的。改完
  必须**再跑一次 lint 复核**。
- 顺手把这条判据加进了 `lint_c.py`（见下），并让扫描范围带上 `.csv`。

### 离线验证分区表（★ 很有用的技巧）

`gen_esp32part.py` 是**纯 Python、零第三方依赖**，可以直接从 IDF tag 下载下来
在本地跑，不用装工具链：

```
python gen_esp32part.py --flash-size 8MB --offset 0x8000 partitions.csv out.bin
→ "Parsing CSV input... / Verifying table..." 退出码 0
```

再把生成的 bin 喂回同一个工具回读，确认自洽。**等于把 CI 里那一步提前在本地
验证掉了** —— 上面那个 BOM 问题就是这么确认修好的。结果：
`ota_0 = 1984K = 2031616 字节`，正好对上 CI 的体积上限。

### 顺带修掉的静默问题

### ★ 推送被 GitHub 拒绝：PAT 缺 `workflow` scope

```

  update workflow `.github/workflows/esp-ams-s3-build.yml` without `workflow` scope)
```

### 环境坑（新）：嵌套分支名建不出来

`git checkout -b feat/esp-ams-s3-idf` 返回 0，但 **`refs/heads/feat/...` 根本没被
创建**，HEAD 变成 unborn（`git rev-parse HEAD` 输出了字面量 `HEAD`），
`git add` 于是把**全仓库文件都标成新增**。差点提交出一个"整个仓库都是新文件"
的提交。改用**不带斜杠的分支名** `esp-ams-s3-idf` 就正常了（`refs/heads/`
下多一层目录在这台机器上建不出来）。
→ **建分支后必须立刻 `git rev-parse --verify refs/heads/<名字>` 和 `git log -1`
   复核**，别直接 add/commit。出问题时的恢复：`git symbolic-ref HEAD refs/heads/main`
   + `git reset`（mixed，**不动工作区**），即可完全还原。

## 当晚 21:19：**推翻「AP 硬件坏了」** —— 热点一直是好的，问题在手机侧

用户又报「还是 AP 连接失败」。这次不改代码，先做**判决性取证**，结论和下午
完全相反：**设备侧 100% 正常**。

### ★ 决定性证据：用独立射频（这台电脑的 Intel AX200）扫

```
netsh wlan show networks mode=bssid
  SSID 1 : AMS_WIFI   WPA2-个人  CCMP   BSSID b4:3a:45:a6:09:b9
          信号 99%   2.4GHz   信道 1
```

- BSSID 与板子自报 MAC **逐字节一致**（板子打印 `b'\xb4:E\xa6\t\xb9'`，
  里面的 `:` 和 `E` 其实是字节 `0x3A` `0x45` 被当可打印字符打出来了，
  别误读成"MAC 少了两个字节"）。
- **两次独立测量**：一次在打断应用停在 REPL 时，一次在应用**正常运行**中，
  两次都扫到、都是 99%。→ 热点在发，而且应用跑起来也不会被关掉。
- 板子侧同时取到的健康读数：`PWRON_RESET`（**不是欠压**）、STA TX 20.0dBm
  （满功率）、`pm=0`、AP IP 192.168.4.1、`max_clients=10`、
  `Web 服务已启动，监听 0.0.0.0:80（3 个 worker）`。

### 下午那套推理错在哪（两条"证据"都是无效证据）

1. **"板子自己 `scan()` 扫不到 AMS_WIFI"不能当证据。**
   实测：APSTA 下板子 `sta.scan()` 结果里 `SELF_SEEN 0`（只看到邻居 6 个网），
   而**同一时刻**电脑网卡扫到它 99%。同一个射频不可能一边发 beacon 一边扫描，
   扫不到自己是正常的。
2. **`ap.config('channel')` 读回 1 也不是故障。** 翻了板子那版 MicroPython
   1.23.0 的 `ports/esp32/network_wlan.c`：读 channel 走**实时**
   `esp_wifi_get_channel()`，写 channel 走 `esp_wifi_set_channel()`。
   信道 1 就是 SoftAP 默认值，而且工作完全正常。它只能说明"set 到 6 没生效"，
   推不出"射频没起来"。
3. 还有一处逻辑硬伤：**STA 能关联路由器拿 IP 本身就必须发帧**，
   "发射侧坏了"和这个观测直接矛盾 —— 当时没把这层矛盾追下去。

### 环境取证姿势（可复用）

- **Win10 的 USB-CDC 板子必须 `DtrEnable=$true`**，否则串口能打开但**一个字节
