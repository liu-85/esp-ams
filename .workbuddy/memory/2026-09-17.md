## 刷机后无 AP：根因确认与修复（延续 09-16 晚 22:30 的串口排查）

- 用户刷的是 CI 固件（release latest = 09e749b「说明」，用户自己 push 的），
  板子起不来热点，串口报 `RuntimeError: Wifi Unknown Error 0x0101`，
  崩在 network_model.py:76 建 WLAN 那一步。
- **根因：0x0101 = ESP_ERR_NO_MEM**（MicroPython 的 WiFi 错误表只认
  0x3001~0x300E，落在外就显示 Unknown Error，非常误导）。
  esp_wifi_init() 要一次性申请约 24KB **连续**堆内存；main.py 先
  `from AMS_WEB import main_task` 把应用加载进堆（吃 ~107KB、切碎堆），
  剩 92KB 空闲也拼不出连续 24KB → 失败。
- **修法**：main.py 顶部、import 应用之前先 `network.WLAN(AP_IF)` +
  `network.WLAN(STA_IF)`。空堆一次成功；之后再调只花 16 字节（对象复用）。
  串口实测：空堆 ~200KB → 成功；WiFi 总代价 AP 24,576B + STA 16B。
- 桌面自测 116/116 过；提交 **6288725**（纯增量，原逻辑原样保留）。
- **板子早上没插**（枚举不到任何串口/CH343）。推板脚本已备好：
  `%TEMP%\push_main.ps1` —— Ctrl-C 抢 REPL → 粘贴模式 base64 写入
  main.py → SHA256 回读校验 → RTS 复位 → 抓 40 秒启动日志 → 自动判定
  （失败关键字 0x0101/Traceback；成功关键字 配置热点已打开/AMS_WIFI/192.168.4.1）。
  板子插上后一条命令完成验证。
- 待办：①板子插上跑 push_main.ps1，确认 AMS_WIFI 出现；②提醒用户 push
  6288725 触发 CI 重编固件（否则下次整烧的还是坏 main.py）。
- 顺手清了根目录临时探针 `_bin_probe.py` / `_boot_sim.py`。
- 串口工具链（都在 %TEMP%，复用价值高）：`mpy_paste.ps1`（粘贴模式执行
  ASCII 代码）、`ams_ctrlc2.ps1`（RTS 复位 + 持续 Ctrl-C 抢干净 REPL）、

## 下午：重启循环修完后，用户反馈「连接 AP 失败」——定位为硬件侧（能收不能发）

启动链已经完全干净（0 复位 / 0 traceback / 0 OSError，热点 0.57s 起来、
Web 2.76s 起来，桌面自测 116/116，提交 51ec834），但手机/电脑**搜不到
AMS_WIFI**。逐层排除，最后确认是**板子射频发射侧的问题，软件无解**：

| 测什么 | 结果 |
|---|---|
| 板子自报 AP 状态 | `active=True`、`essid=AMS_WIFI`、`authmode=3`、`channel=1`、`hidden=False`、`max_clients=10`、`ifconfig=192.168.4.1` —— **全对** |
| 板子自己的 STA `scan()`（AP 关掉时） | **扫到 14 个网**，xiaomi2 才 -40dBm → **RX 正常、天线正常** |
| 板子的 STA 连路由器 | 连上 xiaomi2，DHCP 拿到 192.168.2.153 → **TX 也正常** |
| Windows `netsh wlan show networks` | 反复扫，AMS_WIFI **0 命中**（同批能扫到 2.4G 的 xiaomi2 / FAST_2.4G） |
| Windows 主动 `netsh wlan connect name=AMS_WIFI` | 请求"成功"但仍停在原网络，拿不到 192.168.4.x → 定向 probe 也没回应 |
| 擦 NVS(0x9000+0x6000) + phy_init(0xf000+0x1000) | 无效 |
| **整片 erase_flash + 只烧官方纯净固件**（无任何应用代码） | 裸 AP 依然 0 命中 → **彻底排除软件/配置/应用** |
| 开放网络 / WPA2 / 先 config 后 active / 信道 1·6·11 / 降功率到 2dBm | 全部无效（降功率那次 1/3 是误报，A/B/A 各 8 次复测均为 0） |
| eFuse summary | 正常，无 TX 功率限制迹象 |

- 一个耐人寻味的旁证：`ap.config(channel=6)` 之后 `ap.config("channel")`
  **永远读回 1**（MicroPython 读的是 `esp_wifi_get_channel`，即射频实际
  信道）—— 说明 AP 的射频层其实没有真正跑起来，但 `active(True)` 没报错。
- 芯片：ESP32-C3 QFN32 rev v0.4，40MHz，MAC 9c:cc:01:60:02:d4（esptool 认）。
